The Effect mental model

A compact translation table for an expert TypeScript programmer entering Effect.

The type

Effect<Success, Error, Requirements>
SuccessWhat the program returns if it succeeds.
ErrorExpected failures callers must confront.
RequirementsServices the program still needs before it can run.

The three moves

Describe

Construct inert Effect values. No request has started merely because the value exists.

Compose

Build a larger plan with Effect.gen, pipelines, and concurrency combinators.

Interpret

Run once at an application edge with a runtime, commonly Effect.runPromise during incremental adoption.

Promise bridge

const plan = Effect.tryPromise({
  try: () => existingPromiseApi(),
  catch: (cause) => new ProviderError({ cause })
})

const value = await Effect.runPromise(plan)

Generator translation

// Promise program: already executing
const value = await promise

// Effect program: still a lazy description
const value = yield* effect

Success resumes the generator with value. A typed failure stops it. Requirements and errors propagate into the parent Effect.

Successive yield* expressions are sequential. To introduce concurrency, yield one combined Effect built with Effect.all or Effect.forEach.

Dumgen rule of thumb

Keep an Effect lazy until the application boundary. If leaf modules repeatedly call runPromise, the runtime cannot govern the whole resolution chain.

Do not confuse fibers with durable work. Fibers coordinate work inside one live process. Jobs that must survive restarts still need durable infrastructure.

Bounded concurrency

// A collection of similar jobs
const results = yield* Effect.forEach(
  batches,
  processIntakeBatch,
  { concurrency: 16 }
)

// A fixed collection of Effects
const results = yield* Effect.all(effects, {
  concurrency: 16
})

No concurrency option means sequential execution. A number sets the maximum active children for that combinator. Avoid "unbounded" for provider traffic.

Provider-wide capacity

const semaphore = yield* Semaphore.make(16)

const guardedCall = semaphore.withPermits(1)(
  callOpenAI(request)
)

A combinator limit governs one parent program. A semaphore governs every program that shares that semaphore instance. Build it once in the live provider Layer, then reuse that Layer.
