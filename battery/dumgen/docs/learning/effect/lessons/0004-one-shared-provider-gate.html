Dumgen × Effect · lesson 4

One shared provider gate

Cap OpenAI traffic across every caller, not merely inside one request.

8 minutes · one retrieval check · Effect v4 RC syntax

A semaphore is a bucket of tickets

const semaphore = yield* Semaphore.make(16)

The semaphore begins with sixteen permits. A provider call must borrow one permit before starting. If all sixteen are borrowed, later fibers wait rather than calling OpenAI.

const guardedCall = semaphore.withPermits(1)(
  callOpenAI(request)
)

When the call succeeds, fails, or is interrupted, Effect releases the permit automatically.

Twenty callers sharing one sixteen-permit semaphore can still create 320 waiting jobs—but only sixteen provider calls can be active.

“Shared” is the entire trick

Wrong ownership

Create Semaphore.make(16) inside every request handler. Twenty callers receive twenty independent gates: back to 320.

Right ownership

Create one semaphore in the live provider service at application startup. Every caller reaches the same gate.

Effect Layers are factories for service implementations. Layer instances are memoized by reference, so build the live Layer once and reuse that value. Calling a function that constructs a fresh Layer for every request also constructs a fresh semaphore.

Make capacity a Dumgen requirement

import { Context, Effect, Layer, Semaphore } from "effect"

class ProviderGate extends Context.Service<
  ProviderGate,
  {
    readonly withPermit: <A, E, R>(
      effect: Effect.Effect<A, E, R>
    ) => Effect.Effect<A, E, R>
  }
>()("dumgen/ProviderGate") {}

const ProviderGateLive = Layer.effect(
  ProviderGate,
  Semaphore.make(16).pipe(
    Effect.map((semaphore) => ({
      withPermit: semaphore.withPermits(1)
    }))
  )
)

Any model operation that yields ProviderGate now advertises that requirement in its third Effect type parameter. Tests can provide a different gate; production provides the shared live gate.

Guard the actual scarce operation

const generate = (request: OpenAIRequest) =>
  Effect.gen(function* () {
    const gate = yield* ProviderGate

    return yield* gate.withPermit(
      openAiAdapter.generate(request)
    )
  })

Put the gate around the provider call, not the whole upload workflow. Persistence and local Source Segmentation do not need to hold an expensive provider permit.

Your API key fits the same architecture: the caller supplies a live OpenAI service Layer containing credentials, while Dumgen operations merely declare that they require the service.

What this still does not solve

A semaphore limits active calls in one live process. It does not provide durable queueing, fairness between tenants, cross-process coordination, or survival across deploys. Those require an external coordinator or durable workflow system.
