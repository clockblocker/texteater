Dumgen × Effect · lesson 6

Not every bad outcome is an error

Design Dumgen's success, typed-failure, and defect channels before adding retries.

8 minutes · one retrieval check · Effect v4 RC syntax

Three places an outcome can live

Success

The operation completed and made a legitimate domain decision—even if the answer is “unsupported” or “unresolved.”

Expected error

Normal operational failure that callers may handle, report, or retry. It appears in Effect<A, E, R>'s E.

Defect

A bug or broken invariant. It is retained in the runtime Cause, not advertised as recoverable domain control flow.

Dumgen classification

SuccessAccepted, UnsupportedLanguage, Unintelligible, Unresolved, and NotImplemented are legitimate decisions produced by completed workflows.
ErrorProviderRateLimited, ProviderUnavailable, and an expected invalid provider response prevent the workflow from making its decision.
DefectAn impossible missing item after validated cardinality or a violated internal invariant indicates broken code or assumptions.

“The user did not get the desired answer” does not automatically mean failure. Ask whether Dumgen completed its contract or was prevented from completing it.

The type says what callers must confront

type Segment = (
  sentences: readonly string[]
) => Effect.Effect<
  readonly SegmentationDecision[],
  ProviderRateLimited | ProviderUnavailable | InvalidProviderOutput,
  AiSdk
>

This Effect-native shape avoids representing the same operational failure twice as both { ok: false } and an Effect error. A Promise-compatible boundary can convert the Effect back to the legacy result envelope if required.

Typed errors are ordinary tagged values

class ProviderRateLimited extends Data.TaggedError(
  "ProviderRateLimited"
)<{
  readonly retryAfterMs?: number
}> {}

When sequential Effects are composed with yield*, their error types accumulate into a union. A failure short-circuits the remaining generator lines.

Retry only the transient subset

const resilientCall = providerCall.pipe(
  Effect.retry({
    times: 3,
    while: (error) =>
      error._tag === "ProviderRateLimited" ||
      error._tag === "ProviderUnavailable"
  })
)

Do not retry UnsupportedLanguage: it is already a successful decision. Do not retry a refusal, content-policy rejection, invalid caller input, or broken invariant merely because a generic “retry everything” operator makes that easy.

Retries multiply provider traffic. They must run behind the same shared semaphore and use a bounded schedule with backoff and jitter.

Retrieval check

Where should UnsupportedLanguage live?

  1. A successful domain decision in Success.
  2. A recoverable typed failure in Error.
  3. An unexpected invariant defect in Cause.
