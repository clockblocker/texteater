Dumgen × Effect · lesson 2

yield* is lazy await

Read Effect generator code using a mental model you already own—then learn the one difference that matters.

6 minutes · one retrieval check · Effect v4 RC syntax

The useful lie

When reading an Effect.gen block, mentally replace yield* with await:

const resolveEncounter = Effect.gen(function* () {
  const segmented = yield* dumgen.segment(sentences)
  const grammar = yield* dumgen.grammatical(segmented)
  return yield* dumgen.reading(grammar)
})

Each yield* says: run this Effect; if it succeeds, resume the generator with its success value. If it fails, stop the generator with its typed failure.

yield* is to an Effect what await is to a Promise: it extracts the successful value so the next line can use it.

Where the lie breaks

await promise

The async function is already executing. The Promise operation has usually started. Rejection re-enters JavaScript's exception machinery.

yield* effect

The whole generator still describes an inert program. Expected failures and missing services become types of the parent Effect.

Under the syntax, Effect values participate in the generator protocol. Effect.gen receives each yielded Effect, and the runtime later interprets it. On success, the runtime resumes the generator with the value. On failure, it does not execute the remaining lines.

Your sequential intuition was correct

const first = yield* request("first")
const second = yield* request("second")

second does not start until first succeeds. Generator notation expresses data dependency cleanly; it does not imply concurrency.

For independent work, combine Effects first, then yield the combined Effect:

const [grammarA, grammarB] = yield* Effect.all(
  [resolveGrammar(a), resolveGrammar(b)],
  { concurrency: 2 }
)

Here the parent generator still has one yield*. The yielded Effect internally runs two children with an explicit limit.

What propagates upward

TypeScript infers the parent program from everything you yield:

Effect.Effect<
  Reading,
  SegmentError | GrammarError | ReadingError,
  AiSdk | Dictionary
>

You did not manually write that union. Each yield* contributed its possible failure and service requirement. Providing services or handling errors removes them from the corresponding type parameter.

Retrieval check

What happens when this program is run?

const intake = yield* runIntake(batch)
const grammar = yield* resolveGrammar(intake)
  1. Both operations start at same time.
  2. Intake succeeds before the grammar starts.
  3. Grammar starts before the Intake succeeds.

Choose before reading on.
